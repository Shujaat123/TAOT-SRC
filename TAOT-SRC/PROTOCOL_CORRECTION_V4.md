# Protocol correction in v4

## Why v4 was necessary

In v3, split generation and rotation-angle generation consumed the same random-number stream. As a result, generating a rotated condition could alter later class shuffles, so the clean, +/-10 degree, and +/-20 degree conditions for a nominal seed were not guaranteed to use exactly the same train/test indices. The earlier few-shot cache also allowed the test set to move as `k` changed.

## v4 split protocol

For every dataset and seed:

1. Each class is shuffled once with a split RNG seeded only by `seed`.
2. The first 10 samples per class form the maximum training pool.
3. The next dataset-specific `ntest` samples form the fixed test set.
4. A `k`-shot training set is the first `k` samples of the same 10-shot pool.

Thus 1-shot is a subset of 2-shot, 2-shot is a subset of 3-shot, etc., and the test set is identical across all shot counts.

## v4 rotation protocol

Rotation angles are generated by a second RNG independent of split generation. For each fixed test sample, a factor `u ~ Uniform(-1,1)` is drawn once. The angle for condition `A` is

`angle = A * u`.

Therefore clean uses zero degrees; the +/-10 degree and +/-20 degree conditions contain the same test images and satisfy `angle_20 = 2 * angle_10` sample-by-sample. No minimum-angle remapping is used.

## Consequence

v4 is a new experimental record. It must be validated and rerun rather than numerically compared against v3 reference CSVs.
